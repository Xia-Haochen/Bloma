# 复杂任务交付收尾改进

日期：2026-11-04。依据[两类真实任务试验](complex-real-model-trial-20261103.md)。本轮改善软件生成平台，不直接修改两个实验产物，不新增付费调用。

## 判断与实施顺序

交付流程需要优化。保留已确认任务、阶段累计检查、候选身份、独立C/V、宿主验证和原发布机制；重点改进失败后的动作选择和稳定候选收尾，不引入额外管理层，也不以放宽验证标准减少轮次。

顺序为：已有阶段检查 → 完整业务检查并归因 → 集中修复 → 稳定候选C/V → 重要疑点复现及同案例复测 → 当前版本最终检查 → 宿主发布。需要修复时回到相应环节；建议不自动扩大本轮需求。检查通过与正式发布仍是不同状态。

## 本轮实现

1. **审阅收尾**：`read_quality_findings`增加只读`closeout`，提供必修、待调查、延期意见及下一动作。先处理重要疑点/已确认缺陷，再审阅稳定候选；建议和争议保留在台账，不默认为新增功能。生产提示及`verify_app`反馈使用同一收尾顺序。此视图不签发PASS、不删除意见、不替代发布门。
2. **复现证据**：找不到已运行案例或检查未完成时，保留`suspected`；不再把`unverified`记成`not_reproduced`。原生案例即便先前有成功断言，后续定位超时也不能据此确认finding；须有对应失败断言。运行时异常或源码变化不能作为该finding的通过证据。
3. **失败归因**：明确契约/加载错误归适配层；隐藏选择器等待可见的模式给出等待条件冲突诊断；普通定位超时、遮挡和多匹配保留未知原因，先看实际UI。实际断言失败保留业务检查分类，但提示核对确认预期来源，避免修改产品迎合错误测试。已有冻结输入/断言保护保持生效。
4. **界面验收**：V材料增加布局、交互、内容、覆盖范围四项清单；提交观察必须覆盖四项并绑定同次图片。布局项明确要求检查长路径/长名称对搜索框和按钮的挤压。范围项记录当前页面/状态与未覆盖项，单图不能代表全应用。
5. **界面问题闭合**：已实际复现的中等级V问题也阻塞交付；需当前候选、同规则的通过证据才能关闭。旧V若没有四项记录，不能作为本轮完整视觉审阅依据。

## 能力边界与后续安排

- 本轮清单证明审阅报告覆盖了检查维度，不证明模型观察正确，也没有自动执行所有页面、弹窗和窗口尺寸。已有真实截图传输/授权/完整性规则继续生效。
- 低优先级疑点不是自动关闭；重要疑点先调查。有争议的增强不自动实现，独立B预期争议仍沿现有澄清门处理。
- 失败归因只指导修复位置，不授权改写冻结业务断言；部分等待状态修复若涉及已执行契约，仍需保留阻塞，不能静默重置契约。
- 接下来优先用相同问题的受控回归检查保护机制；再在另行明确的付费范围内复验两个原任务及追加需求回归，观察审阅次数、非必需改动、总请求数、正式交付状态和独立界面结果。当前10元试验账本及未知预留不变。
- 只有复验仍出现重复审阅/修复，才扩展结构化重复失败诊断和有界升级；跨页面多图自动采样、候选差异定向审阅另行实施与验证，不在本轮宣称完成。

## 验证

- 最终定向回归：6文件/44项通过，覆盖`quality-closeout`、`acceptance-feedback`、`quality-review`、`visual-review`、`collaboration-selection`、`verification-tool`。含实际CLI失败/修复、真实浏览器中等级V缺陷复现/关闭、真实PNG通过本机HTTP进入受控模型协议、正常生产发布及未变候选避免重复审阅。
- `npm run typecheck`、`npm run build`、`npm run docs:check`及差异格式检查通过。构建仍报告已有包指令和大chunk提示。
- 首轮验证时本地依赖缺失，按锁文件恢复后使用仓库锁定工具运行。首轮运行期间继续编辑造成模块缓存与新测试不同步；另有一次未变候选父调用次数为2而非1，最终固定代码复跑通过，未定位该次数波动根因，保留为测试稳定性观察，不放宽断言。
- 受控模型只连接本机测试服务，不代表真实DeepSeek交付改善已经实测。本轮新增模型费用为0；没有重跑原两个付费项目或干净机器安装。
