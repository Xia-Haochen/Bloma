## 责任与实际流程

原执行器直接在空白 APP_DATA_DIR 中运行冻结业务案例，缺少模型配置时产生错误气泡，最终被记录为业务断言失败。此次将依赖准备放在宿主执行层，不在每个生成项目的测试脚本里复制配置过程，也不向 B 冻结案例追加设置步骤。

```mermaid
flowchart LR
  A[冻结案例与确认能力] --> B[准备本案例依赖]
  B --> C[启动隔离产品]
  C --> D[通过正常设置界面配置]
  D --> E[执行原冻结业务步骤]
  E --> F[核对实际请求与响应读回]
  F --> G[保存范围明确的结果]
  G --> H[关闭本次资源]
```

- `acceptance-environment.ts`：依赖选择、受控服务、临时凭据、配置准备、就绪观察、请求证据及服务清理。
- `gui-observer.ts`：复用正常 GUI 驱动，在冻结步骤前准备环境；重开沿用本案例数据，不再保存配置。
- `independent-verification.ts`：每个案例创建独立环境，汇总原断言与环境证据；finally 先关闭服务，再清理经过归属检查的临时目录。
- `verification.ts`：仍负责候选完整性、正式验收与结果写回。环境未就绪和产品断言失败分开报告。
- `awaitingAssistedAcceptance`：前端投影、制作循环和实测入口共用下一步判断。B 未准备好时先处理工程，不催用户录音。

没有新增面向 Agent 的执行工具、第二套交付状态机或另一套业务断言。`read_production_context(independent-design/ai-service)` 给出当前声明契约；环境诊断指向相应契约，不让模型猜运行参数或让用户提供验收预期。

## 产品声明

依赖由已确认能力以及 `CORE_CHECK.llm.covers` 与当前案例/关联需求决定。产品登记的是正常设置界面的静态控件绑定：

```json
{
  "llm": {
    "runtime": "node",
    "module": "ai_service.cjs",
    "factory": "AIService",
    "method": "generate",
    "protocol": "openai-chat",
    "covers": ["F-001"],
    "settings": {
      "open": "#open-settings",
      "endpoint": "#endpoint",
      "model": "#model",
      "api_key": "#key",
      "save": "#save-settings",
      "ready": { "selector": "#settings-status", "contains": "已保存" }
    }
  }
}
```

open 可选，仅输入框未显示时打开；protocol 可选，为产品原生协议选择框的静态 CSS。宿主提供本次 endpoint/model/临时凭据，不接受产品声明中的任意执行脚本、远端地址或供应商密钥。

首期支持 openai-chat、anthropic-messages 文本对话，以及 nonempty/observed 类输出观察。固定模型内容预期不能由通用受控服务生成答案迎合，会返回环境不支持并保持原预期。视觉、流式、多服务场景需明确实现对应依赖适配，不能默认为已覆盖。

## 隔离与证据

每个案例独立 APP_DATA_DIR、用户目录、服务端口和随机凭据。服务只绑定 127.0.0.1，没有远端转发，不读取用户真实配置、数据或 API Key。它验证协议路径、鉴权、模型标识及用户消息，限制请求数量与大小。

准备经产品自身设置入口完成，包含实际保存与就绪提示。业务步骤执行期间必须观察到合法服务请求，并从业务观察中读回本次随机服务回复；静态非空气泡不能签发通过。受控回复不从冻结预期或业务需求生成。配置阶段的请求与业务阶段请求分别记录。

证据包含模式、配置摘要、实例身份、就绪状态、请求/响应摘要。报告不保存凭据和请求正文；临时目录内的配置由产品自身存储，案例结束即随隔离数据清理。取消、启动失败、准备失败、案例失败及正常完成都经过同一资源收口。

这些机制是进程与数据隔离，不是对恶意生成程序的操作系统安全沙箱。

## 判定与历史失败

设置绑定缺失、设置未完成、协议不支持或未观察到服务收发返回 environment/unverified，不制造产品缺陷确认。正常业务断言仍按冻结预期判断。

报告标注 `registered_cases_with_controlled_service`、`external_model_effects: unverified`。passed 只表示此环境下登记案例通过，不表示真实供应商、角色效果或听感通过。缺陷台账按已复现失败的环境模式及配置摘要匹配：新环境失败单独留存，并能由同环境复验正常关闭；受控服务通过不能关闭未知环境的历史失败，也不能通过更换服务配置消掉旧失败。
