# Bloma 工作区雾面材质与交互精修实施文稿

日期：2026-11-01（北京时间）。状态：**预案方向已认可，正式 UI 待实施**。

本次将正式工作区精修为清晰、克制、略有材质层次的应用界面。保留左侧大预览、右侧角色对话、顶部五条阶段进度与原有小漫画；文档、材料、版本、协作等覆盖面板采用雾面玻璃，只隐约透出底色，不显露背后的文字、按钮和轮廓。主页保持现状。

用户本次要求是汇总形成实施文稿。本次交付仅包含本文及评审参考，不执行正式界面改造，也不改变真实项目、模型渠道、执行状态或交付结果。

## 一、最终设计依据

### 1. 决策优先级

后续实施以本节和最终雾面预案为准。早期探索仅用于理解取舍，不得把被否定的元素重新拼入方案。

| 已确定方向 | 实施含义 |
| --- | --- |
| 喜欢 Apple 应用的质感，同时希望鲜活 | 用排版、对齐、材质层次和短促反馈体现完成度；不是仿造 macOS 窗口按钮或整套品牌视觉 |
| 角色特色保留 | 复用 Bloma 现有角色素材，与最新真实发言相联系；不添加房间背景或视觉小说场景 |
| 作品展示不能小 | 优先回收标题、重复状态和工具栏占用的空间；不以加高窗口、裁切作品或缩小文字达标 |
| 原条形进度和阶段小漫画保留 | 五条横向细线继续承载真实阶段状态；漫画仍支持悬停、固定、放大及工作记录入口 |
| 覆盖主工作区的组件可以有玻璃质感 | 文档、材料、版本、协作、阶段详情等共用一套雾面覆盖层；不是只给一个工具条做效果 |
| 最终选择雾面、隐约透色 | 移除明显折射、透字、透按钮和背景重影；保证长文阅读清晰 |
| 主页先不改 | 首页布局、文案、导航、输入与导入流程不纳入本轮重构 |

### 2. 已否定的方向

- 整体改成游戏房间、花房背景、巨大立绘或底部视觉小说对话框。
- 用竖向步骤替换横向条形进度，或丢失阶段漫画。
- 大面积强透明玻璃，让底下的文字、按钮和人物穿透面板。
- 强折射、色散、持续流光、彩色光晕及层层玻璃嵌套。
- 把“高级感”简化为大留白，导致作品画面更小；或把所有文字都调成浅灰、浅绿。
- 把 Apple 质感等同于亮蓝色按钮。当前方向是暖灰白、深灰正文、低饱和鼠尾草绿操作色，灰紫主要由角色自然提供。

## 二、范围与功能边界

### 本轮实施范围

1. 工作区布局、标题与状态密度、预览工具组织、右侧会话层级。
2. 工作区专用颜色、字体、间距、边界、阴影和雾面材质。
3. 文档、参考材料、版本、工作记录、协作、阶段详情等面板的统一呈现与操作反馈。
4. 阶段漫画切换、文档选中反馈、Esc 退出、图标说明及协作详情导航的交互补全。
5. 保留并回归现有预览、标记、附件、语音、复制、历史、从消息新开讨论、确认与续跑等能力。

### 不纳入本轮

- 首页、项目管理页、设置业务的整体重做；可保留现有跳转，不换成预案页面。
- 生成软件本身的配色与布局。预览中语音球的黑色背景、蓝色按钮属于作品，不随宿主主题强制改色。
- 更换角色形象、重画阶段漫画、引入大背景插画。
- 改造编排器、模型路由、计费、权限、验收门禁、任务恢复或交付状态判定。
- 为展示新 UI 自动继续真实任务、调用付费模型、开启麦克风或迁移真实项目数据。

## 三、工作区结构

### 1. 常驻区域

- **顶部**：保留品牌／返回主页、当前项目及项目切换、五条阶段线、资料类工具入口。收紧高度，避免品牌、项目标题和阶段说明各占一整行。
- **左侧作品区**：连续中性底板，使用实际 PreviewPanel／交付面板。标题、试用入口和当前作品身份尽量在一条紧凑工具区内表达。
- **预览工具**：适应窗口、完整画布、原尺寸／缩放、标记、专注按实际能力组织。可以采用紧凑停靠工具条，但不能挡住作品操作或挤掉预览高度。
- **右侧对话**：常驻真实消息与输入；人物只陪伴当前短发言，长说明在下方使用完整栏宽。保留完整历史与消息操作。
- **状态摘要**：集中表达“停在哪里、原因、可采取的动作”。详细检查证据和长期维护信息按需展开，避免在标题、作品面板、会话提示中重复堆叠。

状态收敛是显示层组织，不得删改原始日志、截断真实消息或把“需处理”美化成“已完成”。普通暂停不自动等于验证失败；草图可看、独立试用可用和正式交付完成应明确区分。

### 2. 空间基线

本次预案在实测约 **1023×739 CSS 像素**的窗口中，默认完整作品预览为 **707×443**；这是该固定案例的视觉参考，不是全部项目的验收结果。

实施使用同一尺寸、同一画布比例、无工具面板展开、无自定义栏宽的对照案例，目标是不低于此预览面积。其他尺寸以实际可用空间等比适配，不强行写死 707×443。已有用户会话栏宽度偏好继续生效，不为达到演示指标覆盖用户设置。

必须保留：拖动调整会话宽度、键盘调整、双击恢复默认、专注预览、适应窗口与原尺寸查看。切换专注／窄屏视图不得卸载 iframe 或清空输入草稿。窄屏使用作品／对话分视图，不靠横向溢出或纵向拉长伪装桌面效果。

### 3. 覆盖区域

文档、材料、版本、协作等检查面板优先停靠在**作品区域内部的右侧**；保持右侧会话位置稳定，不推挤作品造成反复重排。打开时覆盖部分作品是正常行为，关闭后恢复原有预览、缩放和滚动位置。

阶段漫画锚定对应进度线，弹层始终约束在窗口内。浮层、侧面板、确认对话框需建立明确层级，避免多个面板彼此遮挡、关闭一个却误关全部。

## 四、视觉与雾面材质规范

### 1. 材质分工

| 区域 | 材质与要求 |
| --- | --- |
| 主作品底板 | 稳定暖灰白实体底色，不加纹理、景物或大面积装饰光效 |
| 常驻会话、输入和长正文 | 清晰实体或接近实体的浅色底，正文深灰，保证阅读与输入对比 |
| 顶部与预览工具条 | 轻微雾面、细边缘高光和浅投影；强调操作层，但不制造厚重浮岛 |
| 文档／材料／版本／协作覆盖面板 | 厚雾面，只有大尺度底色轻微影响表面；背景文字、按钮、图标不可辨识 |
| 阶段漫画与详情弹层 | 同一雾面体系；漫画图片不透明、不变形，状态与说明清楚可读 |
| 确认对话框 | 优先保证决策信息与按钮清晰，不能以通透效果削弱风险、费用或确认边界 |

雾面初始调参参考认可稿：浅色覆盖透明度约 **0.91–0.94**，背景模糊约 **64px**，饱和度约 **0.58**，辅以一条轻亮边和低强度阴影。这些是起始值，最终按真实 Electron 合成效果、可读性和性能调整，不能把“参数相同”当成视觉合格。

**硬要求：在蓝色按钮、绿色语音球、长文字和滚动内容后方打开面板时，不能辨认背后的字形、按钮边缘或图标。**只能感到很弱的色温／色块变化。禁用明显位移折射与 RGB 色散。

不支持背景模糊时回退到清晰的实体浅色面板。不把不透明正文卡片再做成多层玻璃。尊重减少动态效果设置；若现有产品提供减少透明设置，应沿用，不另建与全局冲突的主题开关。

### 2. 色彩、文字与角色

- 工作区基础色向暖灰白收敛，例如预案中的 `#f3f3f0`、近白正文表面与深灰正文。操作强调色参考 `#6d8268`，hover／pressed 使用同一色系的深浅变化。
- 文本以中性深灰为主，不把所有次级说明都染成浅绿色。正文建议 13–14px，辅助信息约 11–12px；重要状态不能靠降低透明度表达。
- 使用现有系统字体栈。保持 Bloma 品牌字标，不引入 macOS 专用字体文件或仿造红黄绿窗口按钮。
- 复用既有角色图；最新发言旁约 120–140px 宽作为起始参考，按实际布局调整。人物不得压正文、遮输入或覆盖作品按钮。
- 收起人物后回收空间，并保持草稿与阅读位置。姿态变化必须与真实发言／阶段关联，不随输入、缩放或重绘随机变化。

## 五、交互实施要求

### 1. 已有能力继续保留

正式 UI 已有 hover、按压反馈、面板过渡、主页／项目入口及漫画交互。本轮补缺口和统一体验，不以“重新设计”为理由全部重写。

按钮区分默认、悬停、按压、选中、禁用、键盘聚焦；静态标题和说明不使用假链接光标。悬停反馈约 120–180ms，面板展开约 160–220ms，可中断；不做持续流光或循环装饰动画。鼠标 tooltip 和键盘可访问名称同时具备，触屏不依赖 hover 才能发现必要功能。

### 2. 五项实机问题及修复目标

本会话直接操作正式 Bloma 的「桌面语音球」工作区，并核查对应源码。正式实现前应在新基线再复现一次，避免其他并行修改已经解决问题。

| 问题 | 已观察的证据 | 修复与验收 |
| --- | --- | --- |
| 漫画固定后切阶段误关闭 | 点击“需求”固定，再点“界面”，弹层消失；hover 先更新 open，点击又命中同阶段关闭判断 | 分开管理悬停目标与固定目标。点击另一阶段直接切换并保持固定；再次点击当前固定阶段才关闭 |
| 文档选择反馈不可见 | 点 `task.md` 后正文出现，列表几乎无选中差异；选中背景与面板均为白色 | 使用专用选中色与适当语义状态；正文显示文件名／来源。不要把焦点边框冒充选中态 |
| Esc 退出不一致 | 漫画支持 Esc；文档面板实测不关闭，X 可以关闭 | 顶层轻浮层／检查面板统一支持 Esc，关闭后焦点返回入口；专注模式的退出也统一处理 |
| 协作详情缺少后续路径 | 展开后为任务目标和委派／子会话 ID，没有从此处进入执行过程的入口 | 提供只读子会话历史／结果入口，并可返回原协作项。不存在、归档或加载失败时明确说明，不静默跳空页 |
| 四个纯图标无鼠标名称提示 | WorkspaceShell 的文档、材料、版本、协作按钮有 aria-label，但未设置 tooltip/title | 为四个图标补简短名称与状态提示，保留原有选中底色和键盘语义 |

文档列表本来常驻，**不应误报或重做“返回文档列表”**。只有真正进入子页面或层级详情时才新增返回路径。协作面板缺入口，不代表整个应用完全没有子会话访问能力；优先复用已经存在的消息／会话导航。

### 3. 阶段与弹层状态机

- 保留需求、界面、制作、验证、交付五条横向线及当前五组漫画。
- 沿用真实阶段投影：完成、运行、待开始、需处理含义清晰，不能按时间自动推进。仅实际运行阶段允许进度动效，暂停与等待确认静止。
- 悬停或键盘聚焦可以预览；鼠标经短间隙进入弹层时不关闭，移回取消关闭计时。
- 点击固定；固定时跨阶段悬停不应抢走当前内容，点击另一阶段明确切换。
- 漫画放大保持原比例；窄屏必须能查看和关闭，不横向撑破整个应用。
- Esc 先关闭最上层临时界面，再处理下层面板或专注状态。不得让同一次按键顺带取消录音、终止生成或吞掉输入法操作。
- 关闭后恢复触发控件焦点，避免 focus 事件立即把漫画重新打开。
- 查看漫画、文档和记录全部是读取行为，不触发模型请求、阶段推进、回滚或重跑。

### 4. 内容与导航反馈

保留完整消息。长技术说明可增加摘要／展开层级，但原文、错误详情和复制入口可达，不能用固定“已保留”台词替换模型输出。空内容发送、忙碌状态与停止按钮继续按现有业务规则处理。

资料详情若有多级导航，应保留上级位置；关闭面板回到作品，不能丢失文件选择、预览缩放或输入草稿。只读检查面板与真正模态确认区别处理，不机械地把所有侧栏都变成阻断整个工作区的对话框。

各批次只提交该批相关内容，验证完成后本地 commit；未经另行授权不 push。遇到业务链缺陷先记录并区分范围，不借 UI 改造绕过权限、预算或交付条件。

## 八、验收清单

### 视觉与空间

- [ ] 实测客户区 1366×768、1440×900、1024×768；另用 1023×739 对齐认可稿基线，记录真实 CSS 尺寸和 DPI，不只记录窗口请求值。
- [ ] 默认关闭工具面板时，同一固定画布的完整预览达到空间基线；不靠裁切、变形、缩字号或加高窗口。
- [ ] 390px／320px 分视图无整体横向溢出，确认、输入、关闭与返回可达。
- [ ] 人物不盖正文；长消息、收起人物、调整栏宽和专注切换不丢草稿，不重建现有 iframe。
- [ ] 各覆盖层分别跨过长文字、按钮、深色作品及高饱和区域检查：仅隐约透色，无可辨认字形／按钮轮廓／重影。
- [ ] 无模糊能力时实体回退正常；减少动态效果下没有持续或弹性位移动画。
- [ ] 主页、其他全局页面及生成作品未被工作区样式影响。

### 交互与状态

- [ ] 需求固定 → 界面点击：切换而不误关闭；悬停移入、键盘固定、放大、外部关闭和 Esc 焦点恢复均通过。
- [ ] 暂停不流动；未知、不适用、待确认和失败状态不被显示为完成。
- [ ] 四个工具图标有 hover／focus 名称说明和明确选中态。
- [ ] 文档选中项与正文文件名一致，切换后可辨认；读取失败、空内容和缺失文件有正确反馈。
- [ ] 各面板关闭后回到原工作位置；嵌套详情可返回，不把所有读取面板都强制阻断会话。
- [ ] 协作详情可查看实际子会话／产出并返回；不可访问或无记录时不伪造内容。
- [ ] 输入法、Enter／换行、附件、录音、复制、历史、消息新开讨论、停止、确认和续跑保持原有行为。
- [ ] 只读查看和 hover 不产生模型请求；回滚、恢复或继续制作仍走既有用户动作和宿主业务链。

### 验证与证据

复用并按变更补充 `workspace-progress.test.tsx`、`theatre-workspace.test.tsx`、`document-panel.test.tsx`、`conversation-width.test.tsx`、`sketch-viewport.test.tsx` 等相关测试；协作导航补真实状态和缺失记录分支。不要为单纯配色写镜像 CSS 实现的测试。

完成 typecheck、构建、相关回归与项目要求的检查。用隔离的 PROMA_HOME／用户数据进行 UI 回归，再对真实项目做不触发制作的只读外观核对；不要修改用户真实输入来制造测试状态。`scripts/verify-workspace-studio.mjs` 可作为已有入口，运行前核实其当前行为和覆盖范围。

证据至少包含：构建版本、实际视口、默认工作区、文档／材料／版本／协作四面板、漫画固定与切换、深色背景雾面、长消息、专注及窄屏截图。测试总数不混加重叠结果；预案检查、离线界面回归、真实模型交付分别报告。此次文稿整理不宣称任何正式 UI 改造已通过验收。
