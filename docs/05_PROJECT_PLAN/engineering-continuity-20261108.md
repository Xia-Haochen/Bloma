## 实施边界

负责人负责问题选择、集成与复测；伙伴负责针对未知的独立调查；宿主供给事实、接续材料、预算与确定性收尾。复用现有质量账本、工作区、提案状态和验证出口，不增加监督角色、制作方审批工具或第二套 PASS 状态。

- 工作状态提供已有重要发现的触发条件、证据与后续记录，明确历史材料不代表当前仍阻断或已通过；完整内容仍由共享质量读取入口提供。
- 新伙伴工作区带入最近同项目、同范围的调查笔记、探针及执行记录；排除私有对话、依赖、数据和递归历史，记录版本差异及截断。材料只读，复制不赋予当前验证权威。
- 宿主通过既有单轮 JSON 调用组件独立审查测试更正。输入为冻结前后测试、确认预期、实际验证摘要和执行资源，不带制作方/伙伴对话或写工具；制作方理由仅作待核查主张。复用生产预算和外层金额保护。
- approve/reject 写入既有提案；defer/格式错误/取消保留 pending，不盲目重试。独立模型身份单独标明，不冒充人工裁定。批准只允许原有精确应用与完整复验，不关闭旧失败、不签发产品通过。
