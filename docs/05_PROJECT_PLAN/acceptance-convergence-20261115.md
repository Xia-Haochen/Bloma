# 测试与验收职责收敛

实施基线为 64bca02。本次依据两轮语音项目的实际重复执行、审阅中断和测试修订记录进行重构。付费制作保持暂停。

## 目标架构

确认需求 → 制作与调试 → 正式执行 → 候选审阅 → 宿主结算 → 交付。

正式执行失败返回具体失败。候选审阅负责一次核对实现、测试覆盖及既有问题与案例的对应关系。缺案例直接返回补测，有对应案例则用当前可信执行回执结算。最终视觉判断继续使用实际图片。

| 模块 | 唯一职责 |
| --- | --- |
| verification | 执行并保存绑定当前输入的事实，校验后复用事实 |
| quality-review | 核对实现与覆盖，在一次候选意见中绑定已有问题 |
| quality-settlement | 依据可信案例结果结算问题 |
| quality-closeout | 从当前证据派生下一步 |
| test-corrections | 保护原业务输入与断言，裁定有意语义修订 |
| release-store | 校验实际候选与资格后发布 |

自动制作流程移除独立 coverage 和 binding 审阅阶段。历史记录仍可读取，旧局部意见不能充当最终候选审阅。长期阶段测试继续真实执行，最终候选统一接受审阅。

## 实施顺序

1. 合并自动审阅调度，当前候选审阅同时处理覆盖和问题绑定。一次审阅明确无案例的疑点直接返回制作方。
2. 复用相同候选的可信实跑事实，保留语音资源及实体录音有效性核对。取消、失败、输入变化以及宿主实现变化使旧事实失效。
3. 归并完全相同的重复发现，保留不同触发、不同预期及历史失败。相似文字不作为自动销案依据。
4. 校验测试适配和修订路径。确定性的定位与等待适配沿用契约比较；语义修改仍须独立判断。裁定不能以其他案例失败代替契约保持判断。
5. 用实际 CLI / 浏览器及受控模型重放失败、修复、审阅、结算和发布，验证审阅次数与执行次数，并检查旧台账兼容。

## 验证边界

本批保留整套正式执行，优先消除重复调度。按案例选择性执行涉及共享前置和依赖识别，作为后续设计问题记录，不在本次引入另一套执行器。

必须验证无变化时复用、已确认失败保留、错误绑定拒绝、测试修订后重新执行、审阅中断可恢复、旧局部意见不能签发最终资格、原发布入口仍校验候选字节。真实模型效率和新项目全流程成功需要后续获得授权的付费验收证明。

## 当前实施

自动流程只派发 candidate C/V。已完成的当前候选意见同时承担覆盖与绑定；缺少对应案例时返回制作方，历史局部审阅不能替代候选资格。阶段执行移除覆盖审阅回调。

语音回执移除进程内请求哈希表，改为从持久回执、当前输入、候选字节、语音资源及有效麦克风凭据判断复用。完整资源校验继续执行。

相同目标、需求、预期、触发、复现步骤、位置和严重性的未决重复报告沿用原问题 ID，保留原失败历史。不同位置或触发继续独立处理，已结算问题再次被报告时形成新观察。

候选审阅收到执行报告及冻结测试索引。waitForFunction 第三个参数中的有界等待选项纳入现有适配比较，页面函数和第二个数据参数仍属于冻结逻辑。模型对语义修订仍可能误判，此处没有用文本关键词自动推翻裁定。

## 本地验证

七个相关测试文件的 130 项回归通过，覆盖候选审阅、问题结算、验证工具、测试修订、实体录音接续、独立验收与长期交付。关键新增链路使用实际 CLI 执行及受控 Pi 响应，历史未决问题在一次候选审阅中绑定，经宿主结算后从原发布入口交付；制作方只需一次 verify_app。

有界等待适配、原业务输入保护及语音跨请求复用通过定向回归。最后收紧已结算问题的归并边界后，另行复跑重复发现及候选发布链。类型检查、主进程构建和文档检查通过。本轮未恢复付费项目。
