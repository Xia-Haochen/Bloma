## 2. 用户最终决定

用户想要“高级、鲜活、有审美、没有模板式 AI 感”，明确喜欢 Apple 应用的质感。最后认可的是：

1. **保留左作品、右对话的工作区基础结构。**减少重复标题、状态和套框，把空间还给作品。
2. **大预览优先。**统一窗口下，后期预案的默认预览约为 707×443，窗口实测约 1023×739 CSS 像素。实际落地按相同比例与可用空间验收，不能靠加高窗口、裁切作品或覆盖用户栏宽偏好达标。
3. **保留现有角色特色。**人物自然融入最新真实发言，长正文保持完整栏宽；可收起，不遮输入、正文与作品。
4. **保留顶部五条横向进度和原有阶段小漫画。**用户特别喜欢这一机制，不改成竖向步骤；保留悬停、固定、放大与工作记录入口。
5. **覆盖工作区的功能面板统一雾面质感。**包括文档、材料、版本、协作、阶段详情等。最后要求是“隐约透色就行，别透出后面的文字和按钮”。
6. **色彩统一。**暖灰白底、深灰正文、低饱和鼠尾草绿操作色，灰紫由角色自然提供；不重新加入突兀亮蓝或多彩光效。
7. **主页先不改。**主页预案做过，但没有获得本轮实施授权，不能顺手替换正式主页。

用户对最终雾面预案回复“可以了”，随后要求“综合一下前面所有形成实施文稿”，再要求本交接。这是当前停点，不应回溯执行中途被撤回或改向的旧指令。

## 5. 正式实机检查发现

本会话曾启动正式 Bloma，读取「桌面语音球」工作区并点击文档、阶段漫画及协作面板。查看操作没有发送制作消息或启动付费模型。下列观察与对应源码已交叉核对，接手仍应在当前构建复测：

| 缺口 | 复现／说明 |
| --- | --- |
| 漫画固定后切阶段误关闭 | 点击“需求”固定，再点“界面”，弹层消失。hover 先改变 open，随后点击命中当前阶段关闭条件 |
| 文档选中态不可辨认 | 点 `task.md` 后正文出现，但选中白底与面板白底相同；正文文档分支未显示当前文件名 |
| Esc 行为不一致 | 漫画支持 Esc；文档面板按 Esc 未关闭，点 X 可关闭 |
| 纯图标缺名称提示 | 右上文档、材料、版本、协作有 aria-label，未提供鼠标 tooltip/title；已有 hover 底色不能代替说明 |
| 协作详情缺后续导航 | 只展开任务目标和委派／子会话 ID，该面板没有进入子会话过程或产出的入口 |

不要误报：正式界面已经有 hover、按压反馈、面板过渡和主页／项目导航；文档列表一直在上方，不是缺“返回列表”。协作面板无跳转不等于整个应用都无法查看子会话。

截图中的暂停和音频检查失败只描述当时界面，不代表当前后端问题仍未修复。不要把这个 UI 案例变成未经授权的音频修复或真实任务续跑。
