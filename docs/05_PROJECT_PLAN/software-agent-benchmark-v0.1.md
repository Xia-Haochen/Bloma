# 复杂软件任务 Benchmark v0.1

状态为协议草案。先冻结任务、评分与条件，再执行对照。本协议的预算数字是建议的实验配置，实际付费执行使用另行确认的总额度。

## 测量目标

评估 Agent 能否根据普通用户需求，自主交付满足复杂业务场景的软件。结果面向 Bloma 和通用 Agent，外部验收使用相同业务标准。Bloma 内部的 completed、审阅通过和发布状态作为过程记录。

采用两个独立比较口径。

| 赛道 | 固定条件 | 可以支持的结论 |
| --- | --- | --- |
| H，同模型比较 | 主模型、模型版本、推理档位、上下文上限、可用外部模型集合、费用与时间上限相同 | 该模型与任务集下的 harness 差异 |
| P，产品比较 | 相同需求、交付形态、输入数据、机器、时间与可核算费用上限，各 Agent 使用预先登记的常用配置 | 整套产品的用户交付效果 |

无法控制模型或完整费用的闭源产品只能列入 P 赛道，并标注不可控项。各自后台子 Agent、审阅、失败重试和自发调用均计入时间与费用。记录各角色实际模型，H 赛道增加额外模型须同时向对照组开放。

## 主指标与百分制

主指标为预算内自主完整完成率。一个任务的所有 mandatory 检查通过，证据属于预算截止时的同一交付快照，且没有人工技术帮助，才算自主完整完成。

百分制用于解释进度，固定为业务主链 60、异常恢复 20、数据持续性 10、可使用性 10。各项权重与具体检查在 tasks.v0.1.json 中预先登记。单项检查的多个断言全部满足才得该项分数；权重按业务场景分配。fail 与 unverified 都得零分，报告中分别显示。完整成功由 mandatory 判断，百分制没有另设及格线。

记录四个独立结果。

- artifact_complete，最终软件满足全部 mandatory 检查。
- autonomous_complete，在时间及金额上限内完整完成，人工技术帮助次数为零。
- quality_points，0–100 的场景完成分及各维度分。
- execution_status，完成、超时、费用用尽、Agent 错误、外部设施失败或用户中止。

费用、时间和人工介入单列，不能用低费用抵消业务失败。相同成功水平下比较效率，报告成功样本的时间中位数、全部尝试的总费用及每个成功交付的总成本。没有成功时每成功成本为未定义。

## 初始复杂任务集

机器可读任务与逐项评分位于 tests/fixtures/software-agent-benchmark/tasks.v0.1.json。三个任务各占总榜三分之一权重，覆盖语音服务协调、多对象业务一致性，以及批处理与中断恢复。

每项至少包含三段跨模块用户旅程、两种异常、真实进程重启和持久化验证。任务只约束业务行为、数据与交付形态，框架与组件由 Agent 选择。

所有业务预期、输入格式、必要设备动作与错误情形对双方公开。独立验收可以保留未公开的测试数据实例，但只能改变公开范围内的值。新预期必须升级任务版本，并使所有参赛系统重新评估该版本。

## 公平运行

1. 每个 trial 使用全新工作区、会话和独立数据。目标任务的旧源码、旧解法和之前失败提示不进入试验上下文。
2. 预先登记 Agent 版本、代码提交、模型及推理配置、工具权限、插件、系统提示摘要、任务版本、数据种子、依赖镜像、OS 与硬件。
3. 公共运行时、下载缓存和公开依赖可预装，两组可获得相同材料。Bloma 专用组件在 H 赛道应向对照组提供同等可读和可调用条件；若仅 Bloma 使用，则计为平台能力差异，在 P 赛道报告。
4. 准备时间单列 cold_setup_seconds。从需求提交到冻结交付的 wall_seconds 包括规划、安装任务依赖、审阅、测试和重试。等待预先登记的人工设备动作可暂停双方计时，必须留起止记录。
5. 允许固定的需求与外观确认、凭据注入及设备参与。用预先登记的回答脚本回应澄清；额外技术建议、修改代码、修测试、重启故障进程均计为人工技术帮助。
6. 被测 Agent 自己的重试属于同一次 trial。操作员为救活失败启动新会话、换模型或改 harness，结束当前 trial，原失败保留，另建版本化运行。
7. 外部验收在被冻结的交付副本上进行，评分期不允许继续修产品。外部验收本身的时间与费用单列。
8. Agent 修改工作区内的开发测试属于正常开发。外部评分器、独立输入和参考答案保存在工作区外。评价业务结果及回归，不能通过修改内部测试获得外部分数。

建议 pilot 使用每次 90 分钟、10 RMB 的双上限；该组合必须在任何对照运行前固定。若希望运行更长任务，应对所有系统采用相同的新配置。人民币费用报告供应商实报金额与未结算责任上界；包月产品同时记录原始 tokens、可核算账单和统一公开费率估值，费用未知的运行不参与费用排名。

## 评分依据与异常

每条通过记录必须包含交付快照 SHA-256、外部检查证据文件及其 SHA-256。允许录屏、截图、HTTP 记录、状态文件和自动测试结果共同举证。依赖的断言不能因前序步骤失败而被视为通过。

主评分优先使用可重复的实际操作和状态检查。语义或视觉判断使用冻结量表、匿名成品和两名独立评判者；分歧留待裁决。模型评判器需要先通过人工标注的正反例校准。缺证据时标 unverified。

语音任务同时报告 controlled_service 与 live_provider。前者验证请求、上下文、错误恢复和呈现，后者验证实际模型回复是否满足公开语义预期。T1 的完整成功要求两种证据都存在。ASR 标准录音直接提供给评分器，TTS 不能充当 ASR 的唯一输入来源。实体麦克风使用相同设备、同一句话和统一操作脚本，设备参与属于预登记动作。

供应商网络偶发中断、测试器崩溃等外部设施故障由独立记录确认，原 trial 标 infra_error 并保留。组件安装、Agent 环境配置、测试脚本错误和 harness 卡死属于被测系统结果。排除设施故障时报告排除数量、原因和按全部计划试验计算的保守完成率，不能只保留成功样本。

人工技术帮助后的成品仍可评分，但 autonomous_complete=false。主动取消的样本标 user_stopped，未取得的证据记 unverified，纳入计划运行的保守分母。

## 周末 pilot 与后续比较

先准备三个任务各自的验收输入、外部检查脚本、可用参考解和至少一个错误反例。任何任务未通过校准时标 draft，禁止把运行得分用于正式排名。

周末可执行三个任务 × 两个系统 × 一次运行，共六次，作为预先声明的小样本 pilot。后续使用每项三个独立种子，共十八次。一次 trial 的含义是从空会话开始的整个预算窗口，内部修复次数不增加独立样本数。

按任务先求重复运行均值，再在任务间取宏平均。主表同时列自主完整完成率、成品完整率、平均场景分、人工介入、耗时和费用。报告每个任务的逐次结果与配对差值。三项任务的小样本不足以支持通用优势或统计显著性声明；正式研究应扩展任务家族与重复次数，并报告不确定性。

语音任务已被用于多轮工程开发，标为 development task。对外证明时应增加未用于调参的任务和数据变体，固定后再跑。禁止从多次失败中只挑最好一次；best-of-k 如需报告，必须单独列全部 k 次成本与定义。

## 与现有工程衔接

已有 harness-evaluation 事件可提供 Bloma 的过程日志。新协议的结果层独立于 Bloma 项目状态，通用 Agent 使用相同的任务、记录格式和外部评分。生产验收与 benchmark 评分不共享发布权限。

当前 tasks 文件状态为 draft，评分脚本只计算已提供的外部观察，不运行 Agent，也不替代观察真实性审计。任务、评分器、数据、预算、模型配置与计划运行集合全部冻结并生成哈希后，才形成一个可比较的 study。

单次计分入口如下。

```powershell
node scripts/score-software-benchmark.mjs tests/fixtures/software-agent-benchmark/tasks.v0.1.json trial.json
node --test tests/unit/software-benchmark.test.mjs
```

trial.json 的字段定义如下，原始记录由外部评估人员或独立执行器填写。

| 字段 | 内容 |
| --- | --- |
| protocol_sha256 | 任务集 JSON 原始字节的 SHA-256 |
| run_id / task_id / seed | 唯一尝试、任务和数据种子 |
| system_id / configuration_id / track | 系统、冻结配置以及 H 或 P 赛道 |
| evaluator_id | 外部评估者或评估器版本 |
| execution_status | completed、timed_out、budget_exhausted、agent_error、infra_error、user_stopped |
| wall_seconds | 按统一规则计算的制作总时间 |
| cost_rmb | 全部制作调用可核实的总费用，缺失用 null |
| technical_interventions | 额外人工技术帮助次数 |
| artifact_sha256 | 评分对象的交付快照摘要 |
| observations | 检查记录列表，每项含 check_id、status、artifact_sha256、evidence |
| observations.status | pass、fail 或 unverified，未提供记录按 unverified |
| observations.evidence | 证据文件列表，每项含 path 和 sha256，path 相对 trial.json 所在目录 |

校准评分脚本的受控测试覆盖全部三项任务、关键项失败后的部分分数、跨快照证据、证据篡改、重复检查 ID、人工帮助、缺失费用、超时与外部设施故障。此测试验证计分实现，任务外部验收器与真实 Agent 表现仍需另行执行。

未完成但在截止前已形成合格成品的运行，可由外部验收确认 artifact_complete；原执行状态照实记录。用户中止与外部设施失败不计自主完整完成。费用缺失时保留成品质量结果，预算内自主完成暂不可确认。

参考方法采用 SWE-bench 的实际产物验证、Terminal-Bench 的独立环境与人工验证任务，以及 Anthropic 的参考解和评判器校准方法。
