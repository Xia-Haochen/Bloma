## 静音验收

原适配器只检查本来就可能无声的绘制，并在保存前解除静音，不能有效证明增量功能。现在：

- `BLOMA_TRIAL_MUTE_SELECTOR` 与 `BLOMA_TRIAL_MUTE_SOUND_SELECTOR` 必须成对设置；未配置静音检查时保持基线验收。后者必须是确认需求中明确应受静音影响、在当前画作上可执行的发声操作。不能擅自选任意回放按钮，把“静音画画”扩大为“禁止全部声音”。若当前确认范围没有可用的正对照，先解决需求语义，不能用原本无声的动作取得PASS。
- 同一个动作依次取得有声、静音、解除后恢复的数字音频证据；静音也要求采样实际发生，避免没有观测数据时误通过。允许静音由增益控制实现，不强迫产品停止创建音频节点。
- 静音控件可使用原生checkbox、`aria-checked` switch或`aria-pressed`按钮。状态不可观察时要求适配真实UI，不静默猜测按钮含义。
- 静音期间重新绘制，保持静音保存，然后关闭实际Electron进程、重开，核对笔画及规则引用，再解除静音验证回放。
- 播放中切换、开关跨重启持久化未擅自成为默认要求，报告明确列出边界，待确认范围明确后补对应案例。

静音增量尚未生成。浏览器回归验证的是验收器，不能替代未来产品的静音验收；现有基线检查也不能代替最新C/V、里程碑确认或发布。
