# 持续工程监视伙伴

## 目标与调用链调查

用户要求伙伴仍是完整Agent，持续旁观制作过程、及时识别偏航，而不是独立审计后才提交长报告，也不是单轮分类器。基线0a2ca48；沿当前仓库修改，保留用户未提交的production-workflow文档。

原链路：lean-production → engineering-partner.begin → startDelegation(research) → engineering workspace → Pi。伙伴只有启动快照，后续事实靠主动查询；onChildMessage到工具回合结束才转交公开文字；跨进程没有原伙伴归属恢复入口。工具摘要只有名称/成败，开发观察只投影日志，未投影实际步骤结果。

## 实施

1. 保留既有研究Agent、独立工具、笔记、探针和Pi上下文。原开关启用后，伙伴收到公开行动及实际工具输入/结果；运行中更新上下文，闲置时有新事实才continue同一子会话。不存在定时轮询、每次观察新建Agent或强制一次调用结束。
2. Pi提供公开响应和工具开始/返回的观察回调；开始只表示请求，不表示执行成功。返回后在观察窗口合并同一工具的参数和结果，原始时序仍在原审计中。用户公开补充与制作方主张分开标记；旧意见出现后若已有新结果，会明确提醒按当前事实判断。成功公开消息可在响应完成时先交接；私有思考、系统提示、压缩内部过程和C/V内部对话不进入监视通道。观察参数使用副本，监视回调修改输入或抛错都不改变原工具/原回执。
3. 伙伴可继续自主调查，也可通过既有ask_delegation_question向负责人提问。无提醒的正常完整响应可安静结束；失败/不完整流仍拒绝，制作方与C/V不获得静默完成豁免。沉默不签发验证结果。
4. 项目活动记录仅新增伙伴归属事件，复用原会话索引、工具审计与Pi会话恢复，不建立第二套执行/通过账本。校验项目、父会话、operation和需求范围；原观察未消费时不会因结束竞态丢失，有新事实才续接，失败调查不自动重复。
5. 开发观察提供真正的steps；调试窗口关闭后保留带historical/stale标记的结果，不能因伙伴目录缺文件就推断没有执行。
6. 登记检查通过后由宿主收尾，伙伴不再新增请求，不阻塞C/V或发布；业务缺口返回制作才恢复监视。沿用原请求队列、费用保护、取消与资源回收，不增加审批或产品状态。

宿主接线合并为childLoopContext：为监视伙伴选择自己的系统说明、原始观察任务及实时上下文，身份、工具和预算仍由既有委派控制。通用委派的“最终结论标记/交接报告”包装不再强加给持续监视器，普通实现和C/V保持原协议。新的工具活动（包括读取）和用户补充可以续接闲置伙伴，运行中合并供给，不启动第二个伙伴；纯应答不单独触发，避免互相回应的空转。宿主不以工具类别替Agent判断哪些调查值得关注；截断/退行输出不自动循环重试。伙伴停歇期间新的生产返回会保留到前一调用完成，不丢失恢复意图。
