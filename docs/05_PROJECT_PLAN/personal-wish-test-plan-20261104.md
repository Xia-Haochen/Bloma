## 1 测什么

核心问题：平台能否在不要求用户编写技术规格的前提下，保留个人愿望的独特部分，并在真实使用、规则变化、中断和数据积累后继续正确工作。

保留11月3日两个本地业务样本为交付链回归，不将其作为开放需求能力代表。此前“囤货审判庭、电脑考古、小说沙盘”仅为公开设计例子，不作为全部验收集，也不允许题材分支成为解法。

## 2 样本结构及隔离

按六类结构选题，每类至少准备一个开发样本和一个同机制不同领域的保留样本。首版12个文本/素材样本用于离线检查，不要求全部进行付费生成；付费批次另行选择并登记预算。保留样本由未参与该次实现调优的评审者/用户选定并封存；若实现者已读过，应标记污染并补新的样本，不能自称盲测。

| 结构族 | 必须具备的结构 | 要主动排除的伪成功 |
| --- | --- | --- |
| 特殊互动与风格 | 至少两条不同使用路径、临时风格切换、事实边界 | 只改标题和台词；交互始终是通用聊天框。 |
| 私人规则与例外 | 对象身份、规则冲突、局部例外、例外期限 | 仅按名称匹配；例外无条件影响所有对象；临时要求永久生效。 |
| 混合素材与来源 | 两种以上素材、冲突或缺失来源、人工纠正 | 编故事填补证据；OCR结果直接充当用户确认事实。 |
| 开放世界与历史 | 有状态演化、规则变更、保留历史或显式分支 | 修改当前规则后偷偷改历史；同一状态出现互相矛盾解释。 |
| 持续任务与真实动作 | 非即时执行、取消/重启、重复输入、部分失败 | 只有进度动画；取消后仍写数据；恢复重复产生副作用。 |
| 个性化信息组织 | 用户自定义关系/视图、检索、纠正/删除传播 | 一律变成平面CRUD；删除后搜索和派生输出继续误用。 |

每份样本分开存放（拟议目录`tests/fixtures/personal-wish/`）：

- `request.txt`：自然、口语化、带个人用词的愿望。只含目标、材料、功能、限制，不注入框架、平台工具名、F编号或隐藏验收锚点。
- `assets/`及素材清单：合成或获授权的材料、原始hash、预期存在的冲突/缺失；制作方能访问实际素材，不能访问隐蔽判定答案。
- `oracle.json`：独立评审预登记的核心体验、规则/例外、可接受实现集合、反例、不确定项、来源引用及执行证据要求。隐藏的是测试步骤和期望映射，不是用户从未提出的需求。
- `changes.json`：后续自然语言改意、恢复与删除操作；到指定阶段才向制作方提供。
- `protocol.json`：代码/提示词/模型/渠道/参数、组件版本、范围、时间和费用界限、停止条件、评审角色与样本污染状态。

## 3 通用测试矩阵

| 层级 | 核心检查 | 关键反例与判定 |
| --- | --- | --- |
| 整理/确认 | 原文来源→功能/规则/体验的关联；简单任务轻量；歧义只在实质阻塞时询问 | 把明确例外降为suggestion；新增无来源承诺；原话全部复制却没有实现义务；模型伪造S引用；用户撤回后旧卡仍确认。 |
| 生产上下文 | 正常制作、压缩恢复、委派、跨会话显式交接 | 只保留功能列表而丢禁止替代；用旧规则版本；子任务只看通用模板；记录“收到材料”冒充理解正确。 |
| 能力组合 | 实际输入输出/取消/错误、开发和产品运行依赖分离 | 组件require成功却无真实处理；开发API可用而成品无配置；本地mock替代真实外部能力；能力不支持时伪造结果。 |
| 产品状态 | 身份与显示名分离、偏好作用域、纠正优先级、来源和派生失效 | 同名串对象、改名丢例外、旧异步结果覆盖新纠正、跨项目泄漏、删除后缓存命中旧事实。 |
| 语义变化 | 新规则引用、影响说明、旧数据读回、历史保持/分支、累计回归 | 改意导致旧功能悄悄消失；历史被重算覆盖；只改文案没改行为；旧scope的验证凭据继续发布。 |
| 体验 | 沿真实核心旅程观察操作及结果，结合截图/录像与输出来源 | 视觉漂亮但主要玩法缺失；只有空页面截图；普通表格外加说明文字冒充特殊工作流。 |
| 收尾/交付 | 重要缺陷闭合、建议延期、证据匹配当前候选、正式终态 | 无法复现被记为没有问题；主观评分覆盖硬失败；verify通过冒充发布；扩大原费用额度。 |

为评审器准备刻意削弱的产物：删掉例外、仅保留角色台词、伪造引用、关闭后失忆、混淆两个对象、取消后迟到写入。若验收仍通过，该验收机制本身失败。也准备外观/实现不同但语义等价的正例，检查是否错误地只接受标准答案。

## 4 执行顺序

UI/UX横向矩阵必须覆盖上述结构族，不能只测试一个标准工作台：

- 指定原始资源：使用实际图片/字体测试文件，检查hash、衍生转换、指定状态可见、离线启动与打包后引用；替换成相似图但未使用指定原图应失败。
- 参考图与内容素材：同一素材分别作为风格参考、必须使用资源、待处理业务内容，验证三种角色不会混淆；图片里的文字不能成为平台指令。
- 特殊风格与交互：至少一个非标准表单布局，包含真正的拖拽、动画或其他被要求的交互；颜色相近但关键体验缺失应失败，符合方向的不同实现可通过。
- 未指定风格：给不同核心旅程，检查默认继承平台语义调色且布局服务用途；不要求彼此故意不同，也不允许workbench样例强制套版或新增无来源功能。
- 调色优先级与版本：无偏好采用平台默认；局部偏好仅覆盖指定项，明确整体风格可替换默认；草图/制作/审阅绑定同一设计版本；平台主题升级不修改已有产品。检查可读性与状态区分，不能只检查色号是否出现在CSS中。
- 明确授权跳过草图：不重复询问已授权设计细节；仍检查指定素材、真实UI和视觉验收。未授权跳过时保留现有确认门。
- 变化及极端状态：更换参考/资源、局部改风格、改窗口尺寸、长名称、空/错误状态、键盘焦点；核对旧设计证据失效与业务行为保留。
- 环境边界：草图模型看不到参考图、格式不支持、字体缺失、资源加载失败时，必须保留明确未验证/阻塞，不能声称已按资源完成。

复用测试入口：`tests/unit/ux-visual-pipeline.test.ts`及现有UX确认/绑定、材料、视觉审阅、产品分发测试；具体新增用例随W0–W3实施。静态HTML预览通过不等于动态体验通过，素材hash通过不等于实际使用通过。

1. **离线契约回归（W0）**：扩展`tests/unit/requirements-model.test.ts`、`tests/unit/guide/lean-guide.test.ts`、`scope-confirmation-ui.test.tsx`、`software/project-decisions.test.ts`等现有入口；验证结构、保留、变更、确认恢复和哈希失效。拟新增`personal-intent-flow.test.ts`检验跨层传递。纯字段通过不报告语义理解成功。
2. **判定器与受控产品（W1）**：扩展独立语义/质量及现有原生GUI测试；执行上述正反产物。核对oracle依据，体验判定分歧必须留理由，禁止由制作方改隐藏oracle使自己通过。
3. **组合和恢复（W2/W3）**：复用`product-foundation.test.ts`、`product-workflows.test.ts`、`product-components-preparation.test.ts`和`release-update.test.ts`，实际文件/进程/浏览器测试输入、纠正、中断、迁移和数据读回。协议用本机受控服务检查；供应商效果单独验证。
4. **真实模型小批次（W4）**：先选两个机制明显不同的样本，其中至少一个保留样本；每个完成初始生成→真实使用→一项中途变更→恢复/重开→正式交付状态核对。若共同基础机制失败，先修机制，保留失败记录，不靠换题获得漂亮结果。
5. **扩展覆盖**：基础链有效后覆盖其余结构族及未见组合。有限样本仅支持对应场景结论；如随机性影响结论，按事前登记再重复，不事后只选成功运行。

## 5 评分与证据

不设一个加权总分作为发布门。按维度记录passed/failed/unverified/not_applicable及证据引用：核心体验、硬业务不变量、来源与纠正、变化与恢复、界面可用性、正式交付。not_applicable须解释与需求的关系。

硬约束的可观察违背必须失败；能力缺失或预算停止保留未验证/未交付，不混同为产品缺陷。主观体验使用来源绑定的rubric：观察到了什么、符合哪条用户表达、有什么反例、哪些仍需用户评价。独立模型可辅助，但不能通过自身评分取代宿主证据或最终用户偏好。

同时记录：遗漏/弱化的核心承诺、无来源新增功能、重要例外保留情况、用户重复解释次数、必要澄清次数、人工修补/重启介入、审阅轮次、请求与总费用、首次可用与正式完成时间。每项比例都保留分母与逐条记录；不能把复跑次数相加当独立样本。

所有报告绑定源码、需求/规则版本、素材hash、模型与环境、测试协议版本。展示哪些仅为fixture/mock、哪些是原生浏览器、哪些实际调用供应商，以及最终项目是否completed/completed。来源素材被删除后的证据留存范围按已确认策略执行，测试报告不意外保留不该保留的正文。

## 6 费用与试验边界

本计划不发起调用，不沿用11月3日窗口、不释放未知预留。真实验收前确定生成/修复/审阅与成品运行AI调用的共同总上限或明确子额度；两类费用均入报告，不能只统计制作费。核对真实路由、价格及完整输入预留，受控服务请求不得记为供应商验收。

停止条件：硬金额准入拒绝、授权取消、已配置重复失败停止、关键环境不可用。保存可运行候选、错误证据和未完成范围；不得重置operation或修改验收预期继续刷样本。
