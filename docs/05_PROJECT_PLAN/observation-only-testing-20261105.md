## 当前方法：允许正常用户交互，禁止外部工程代修

用户已明确，阶段确认和基于实际效果的意见属于测试需要；理想流程由Agent模拟真实用户测试制作效果。当前采用“模拟用户交互、无外部工程协助”的口径，不再把需求确认作为整个试验不可逾越的终点。原只观察段的结果和费用保持不变。

## 动作执行与恢复职责（2026-11-06）

每轮为观察 → 完整校验一个动作 → 执行 → 记录确定/不确定结果 → 重新观察。模型通过原生perform_user_action工具表达下一步用户意图，观察ID由宿主绑定；不再从自由文本解析JSON，模型正文中的虚构system/view或动作均不成为执行输入。每次只接受一个该工具调用；多个调用、错误工具、空调用、无效字段或参数均在执行前拒绝，公开反馈随后交给模型重新决定，不拆批并沿用旧控件编号。每次动作完成或执行失败都会使旧观察失效。待执行动作同时检查控件语义、支持操作及当前可用状态。

执行失败不计为试用；超时/失效页面可能已有副作用，记录effect=unknown后重新观察，不自动重放点击、上传或回复。只有真实完成的应用交互允许进入体验评价；评价仍不签发产品验收。恢复错误使用明确类型，原始原因只留本地证据，模型看到公开解释。生产回复不自动重放；内部未知错误、金额和完整性守卫不进入交互恢复。连续恢复失败有界退出，原金额/时间/累计请求保护保留。

可见语义操作面包括原生summary、关联label的radio/checkbox/file、ARIA控件和可编辑文本。文件选择事件提供真实上传入口，仍只允许固定清单内未变化的文件。标签点击保留浏览器正常遮挡检查，不使用force、DOM点击或产品代码注入。截图、控件描述、每次请求/完成/失败均保留，历史操作带对应目标的公开描述。历史同时保留真实可见文字变化和媒体状态，不仅保留“操作已执行”。可见HTML媒体播放时由宿主采样约1秒的前后画面及currentTime推进；声音仍是未测，不把播放器muted/volume或时间推进解释为真实听感。同一观察状态下，相同非等待动作连续/重复三次仍无新结果，下一次执行前反馈无进展，由代理换操作或结束未验证；等待仍受原期限/预算约束，不强行截断正常异步任务。

已交付项目从活动发布启动并验证发布字节，不重新制作候选。显式续跑冻结当前项目与账本摘要，启动时在跨尝试独占锁内再次校验，防止换项目、换发布、费用变化或并发执行；旧claim、报告、费用保留。运行结束即使用户代理失败，也保存产品生命周期和活动发布，区分“产品已交付”与“用户未完成验收”。锁遇进程崩溃不自动抢占。

## 当前交互契约：可用操作与执行校验同源

FX确认反例后，userActionContract根据当前问题卡片/应用状态同时生成工具schema和解析器。问题卡片仅提供reply/stop，choice枚举当前公开选项，不暴露ref或应用控件操作；仅选择choice即可由宿主补齐该选项已显示的文字，用户补充text时原样保留。自由回答没有choice，应用操作没有卡片choice。每种动作的字段和必填项使用同一组定义，schema中按动作分支约束；过时或错误动作的反馈明确列出当前可用动作、错误字段与合法字段。没有FX专用分支，没有把错误click/select偷偷转成用户确认。
