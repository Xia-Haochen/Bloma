## 改动

1. `quality-closeout.ts`不再将coverage完成或其他规则下的完成当成当前binding工作已审阅；保留最新中断的效力。
2. 从既有台账派生完整`binding_findings`/`binding_work`。独立审阅沿原`resolutions[]`为每条疑点确认案例；相似文字、同F编号或另一个问题closed不能代替逐条确认。
3. `test-corrections.ts`提供已批准、已应用且仍登记于当前范围的差异投影，分开显示案例正文和共享输入；没有继承旧绑定/PASS，也没有增加状态文件或审批工具。
4. `quality-review.ts`在提交处再次核对合同版本；局部审阅材料提示核对能区分错误实现的前置、正文与持久状态。修正case_name描述，明确可绑定未决疑点、已有失败必须保留原案例。
5. `quality-settlement.ts`和宿主诊断详情同时按案例名与requirement筛选观察；结算去重补齐规则和案例维度。一个可信当前报告可以逐条结算多个已独立绑定的问题，未绑定问题不动。

最终candidate C/V、原冻结输入/断言、唯一发布出口、operation、费用与unknown保护均保留。没有新增常驻角色、第二份通过账本或平行交付状态机。上游本地参考版本为Proma`bf3e98ca61dd8365eceaef876c0f7473700878a6`；该版本没有对应software-v1质量台账模块，本批在Bloma现役实现上最小修复，没有整体移植/rebase。
