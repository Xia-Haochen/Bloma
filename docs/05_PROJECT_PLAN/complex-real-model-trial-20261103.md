## 成本与停止原因

- 使用已配置的DeepSeek Flash官方渠道。预检读取模型目录、余额和当时[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，以峰价2元/百万输入、8元/百万输出、0.04元/百万缓存输入作保守计价；没有启用额外B模型或供应商服务端收费搜索工具。
- 金额账本共416条请求记录，其中415条有已报告用量，1条因试验宿主中断仍保留完整预留。
- 已报告用量按峰价计价：**5.681932元**；中断请求预留：**2.228224元**；责任上界合计：**7.910156元**。
- 剩余本轮额度为2.089844元，低于下一请求的完整输入保守预留（还未计必要输出），因此停止模型调用。这里不是账户余额耗尽，也不是已实际消费10元。
- 未用账户余额差直接释放未知预留；原账本和旧实验核对文件保持不变。操作级保护的预留与全窗口账本不相加，未把未发出的准入尝试算成已消费。
- 后续独立页面检查没有模型调用。未启动审批增量或最近阅读筛选变更，未新增预算。

## 过程与人工介入

1. 新驱动首次在生成前读取尚未创建的账本失败，修复初始化观察后沿同一项目继续，没有生成费用。
2. 初轮在截图后使用OpenAI兼容的本地`function`工具格式，被试验驱动误当服务端收费工具拦截。核对协议适配实现后允许`custom/function`两种本地工具格式，仍拒绝收费服务端类型。原incomplete报告保留。
3. 真实阶段2入口调用旧阶段用例时，平台按入口变化一律拒绝，导致模型反复调整测试文件。停止该轮宿主，保留中断预留和全部失败；没有编辑生成产物来过关。
4. 平台修复提交`6c64602`：允许受限的累计入口组合，并返回原入口预览和差异；旧入口、用例、共享逻辑和重开要求仍保留。后续又要求旧入口先执行，拒绝分支、参数改写、先运行新增逻辑及循环。两类入口的真实浏览器测试与反例检查通过。
5. 沿原项目、会话及10元账本恢复。社团候选通过阶段检查和部分宿主完整检查后，审阅/修改继续消耗请求，最终因当前C证据未闭合而保持未交付。
6. 资料任务初次需求整理未形成可接受任务单，重试后成功；原始失败输出未捕获，不能进一步归因。后续驱动加入需求原文输出诊断。制作过程中出现安全扫描及测试失败，最后金额准入停止。

因此，本轮包含驱动修复、一次平台修复和续跑，不能当作无人工介入的一次成功。所有生成产物修改均由被测Agent完成；独立验收脚本不修改产物源码。试验驱动后续增加了请求间`pause-generation`标记检查，以便以后优先在请求边界暂停，减少硬终止造成的未结算预留；本轮已经保留的预留不因此减少。

## 主要启示

1. **当前瓶颈包含收尾效率。** 两个成品的所选核心功能实际可用，却没有闭合平台发布状态。社团任务中低优先建议引出了额外改动和再次审阅，后续应让非必需建议与必修问题的处理更清楚，避免扩大测试义务和反复重审。
2. **冻结规则必须兼顾合法增量。** 新入口合法复用旧入口不等于修改旧断言；本轮已修复这个可复现的平台问题，但没有放宽任意测试改写。
3. **测试适配错误要与业务错误分开。** 资料任务有等待`#import-modal[hidden]`“可见”的超时，这是测试等待语义问题；标题识别和浮层遮挡等问题还应分别核对业务约定与真实UI，不能统一要求修改产品迎合测试。
4. **功能检查不覆盖视觉质量。** 资料候选的搜索框布局仍有可见问题，说明不能省略最终V/独立可用性检查。
5. **预算报告要说明保守预留。** 已报告计价、未知请求责任与下一请求准入是三件不同的事；不能用清账或重建测试窗口解决收口问题。

本轮的两个样本用于定位故障，不用于推断普遍成功率。下一步优先针对收口与测试适配做定向改进，再安排新的明确预算复验；不自动启动新的付费窗口。
