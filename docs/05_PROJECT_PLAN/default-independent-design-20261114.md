## 当前行为

- 新建 software-v1 GUI 项目默认启用 B；B 沿用制作方本次解析出的渠道、模型和单次输出配置，在独立会话中读取确认需求与界面资料，不读取实现文件、不使用工具。设计先于制作冻结，平台随后执行冻结案例。
- 项目显式配置优先，其次是既有全局配置，再次才是新项目默认值。已有独立渠道、模型、额度设置及显式关闭配置不被覆盖。旧项目没有默认标记，维持原模式。
- 配置页面保留两种 B 配置方式：沿用制作模型与项目预算；单独配置渠道、不同模型与独立额度。后一种沿用原有授权与保守预留规则，已有账本保留。
- 默认模式不再要求第二模型或单独填写 B 预算，也没有 B 专属 60 秒设计超时；请求、输出和费用仍计入既有项目共享边界，跟随父任务取消。没有取消项目总预算或供应商额度。每批一次请求、案例结构校验及批次容量仍是协议约束。

- 同一模型的独立上下文减少实现细节对测试设计的影响，但不提供异构模型独立性保证；配置第二模型仍有意义。

## 实现与闭环

`Project.independent_design_default` 仅标记新项目。`independent-policy.ts` 集中处理默认策略和显式配置优先级，`independent-design.ts` 在原设计管线中选择共享或独立计费路径，继续调用原预算封装。未增加新编排器或第二套验收流程。
