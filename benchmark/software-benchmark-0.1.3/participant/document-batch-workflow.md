# document-batch-workflow

做一个本地文档批处理桌面软件。导入多份中文TXT、Markdown和带文本层的PDF，按关键词搜索，查看匹配片段及来源页码或行号。把选中文档交给可配置的AI服务生成逐文档摘要和带来源索引的汇总报告，可导出Markdown与CSV。任务排队执行，可取消和失败重试，退出重开后能看到任务及结果。原始文件保持完整。

## 输入及边界

提供公开编码及格式边界、含重复标题的六份文档、损坏PDF、固定关键词、受控服务、同一真实模型服务和人工核对事实表。

默认使用 Windows 桌面。可用运行时和模型配置以统一 study.json 为准。

## 公开验收标准

- B1（20分） 支持公开的三种文档格式，提取中文内容，重名文件仍保有各自身份，逐文件内容与参考文本一致。
- B2（20分） 固定关键词检索返回正确文件、匹配片段及页码或行号，可打开相应来源，过滤与清空过滤结果准确。
- B3（20分） 受控服务收到所选文档内容；真实模型摘要保留指定关键事实，汇总报告中的来源索引可逐条对应，未选文档不会混入。
- R1（10分） 损坏PDF与不支持编码被准确标明，其他有效文档可继续处理；取消指定排队任务后不会产生伪完成结果。
- R2（10分） 单次模型失败只影响对应任务，可重试并成功；已完成任务不被重复覆盖，原始输入文件哈希一致。
- P1（5分） 关闭全部进程重开后，文档索引、配置、任务状态与已完成结果正确读回。
- P2（5分） 导出的Markdown和CSV包含正确选定结果与来源，中文可正确读取，失败任务有明确状态且不伪造摘要。
- U1（5分） 正常入口可完成文件选择、搜索、提交批次、取消、重试、导出，耗时操作期间界面仍可响应。
- U2（5分） 每个任务可辨认输入文件、排队/运行/完成/失败状态及错误原因，用户能从结果定位来源。

## 公开操作场景

# 文档批处理外部验收

使用inputs/documents中的六份有效文档、一个损坏PDF和一个不支持的UTF-16文件。支持范围为UTF-8 TXT/Markdown及带文本层PDF。文件身份以相对路径区分，a/项目纪要.txt和b/项目纪要.txt名称相同。

| 检查 | 外部操作与预期 |
| --- | --- |
| B1 | 导入六份有效文档，逐份对照facts.json核对中文文本，重名文件内容分别保留。 |
| B2 | 搜索“青禾”，返回facts.json登记的文件及页/行位置；打开每个结果并核对片段。清空过滤后六份文件都可见。 |
| B3 | 选中a/项目纪要.txt、预算.md、交付.pdf，受控服务收到三份内容；使用统一真实模型输出摘要与汇总，核对三份中的关键事实和来源，未选文档的3000元旧预算不得混入。 |
| R1 | 导入损坏PDF及UTF-16文件，标明具体文件问题，有效文档继续可用。受控服务delay_ms=5000，排入至少三项，取消尚未开始的一项，该项不产生伪完成结果。 |
| R2 | fail_next=1，仅当前任务失败，已完成任务结果保留。清除故障并重试失败项成功，已完成项无重复覆盖。运行前后原始文件SHA-256一致。 |
| P1 | 所有任务结束或取消后关闭全部产品进程，重开读回文档索引、配置、每项状态及已有结果。 |
| P2 | 导出所选结果为Markdown与CSV，逐文件核对中文、来源与状态。失败/取消项不能被写成成功摘要。 |
| U1 | 导入、搜索、排队、取消、重试、导出均走正常界面。运行中尝试选择其他文档，界面仍响应。 |
| U2 | 每项任务的输入身份、状态及错误可见，结果能定位来源。 |

把实际导出及UI观察转换成document-facts.json供自动核对，保留原始导出和对应录屏。自动核对仅覆盖事实与文件映射；模型语义、来源可操作性、取消和UI响应由外部步骤验证。


交付时提供正常启动入口、依赖说明和本机数据位置。
