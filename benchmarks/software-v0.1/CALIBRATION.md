# 校准范围与正反例

评分标准、公开输入和外部操作脚本按本包版本固定。任务分值均为100，mandatory 项全部通过才算完整完成。

## 已实际执行的校准

- 自动数值/事实核对器对三项任务执行18项正反控制及真实HTTP服务检查，见calibration/results.json。
- 器材正例固定库存与关联，错误反例分别修改可借量、逾期成员和导入后归还结果，均被拒绝。
- 文档正例固定文件、来源和所选事实，错误反例删除重名文件、改错页码、篡改输入摘要和混入未选预算，均被拒绝。
- 语音观察正例包含三轮完整播放和四项回忆事实，错误反例截断音频、静音和遗漏上下文，均被拒绝。
- 受控服务实际HTTP检查覆盖正常请求、401、单次503后恢复、SSE结束及日志凭据去除。
- 中文PDF输入由独立解析器提取并逐行核对。语音输入在评测前由独立VITS工具合成，保存来源和时长。
- 外部计分器另行测试了证据篡改、重复项、跨快照、人工帮助、超时和费用缺失。

自动核对器的参考数据不充当参赛成品通过的证据。0.1.3新增三个实际Electron参考应用及独立界面运行记录，见calibration/e2e-index.json与reference-evidence。参考源码位于项目tests/fixtures/benchmark-reference，重放入口为scripts/calibrate-benchmark-e2e.mjs。制作Agent不得得到参考源码、评估者工具或校准证据。

## 0.1.3 实际参考链路

| 任务 | 已执行正例 | 实际错误产品反例 |
| --- | --- | --- |
| 器材 | 界面导入/编辑、四笔交叉借用、部分归还、两位成员及逾期查询、三种非法操作原子拒绝、错误CSV取消重试、全进程重启、备份导入空实例后继续归还 | 将可借量错误地返回总量，外部读取界面后拒绝 |
| 文档 | 六份TXT/MD/PDF逐文本核对、同名文件保留、检索与来源打开、逐份摘要与汇总、损坏文件隔离、取消排队项无请求、503仅影响一项并重试、重启后凭据可用、MD/CSV导出、原输入哈希不变 | 将来源位置改成page:99，外部事实检查拒绝 |
| 语音 | 标准WAV真实ASR、请求包含当前及历史双方文本、连续输入顺序完整播放、静音无请求、取消按钮无请求、503/401与配置修复、全进程重启后继续 | 播放0.5秒后主动停止并伪造ended事件；外部进度与时长检查拒绝 |

真实业务模型采用deepseek-flash / enabled / high：文档3次逐份摘要+1次汇总，语音3轮+重启后1轮，共8次请求，全部保留脱敏请求、回复及用量。文档的林舟、300元、蓝色、交付日期及三个来源均出现，未混入旧预算3000元；语音第三轮和重启后一轮均准确回忆语音助手、周五、300元、蓝色。由外部脚本核对事实，并保留原文供独立评判。

语音另保存Chromium音频图实际输出的PCM，逐轮检查非静音、完整时长及自然结束，再用ASR复核实际输出。复核发现未启用VITS数字规则时300会漏读；修复后重新运行全链路并断言音频包含预算和蓝色。真实模型的原始请求与回复保持不变，另用严格匹配请求的原回复重放验证修复后的TTS和重启（voice-replay，无新增付费调用）。这不是新的模型成功样本。

数字证据覆盖浏览器音频播放链路，物理耳机/扬声器听感仍由听音记录说明。取消录音使用Chromium合成设备操作真实录音与取消控件，不能写成实体麦克风采集。用户于2026-11-16确认麦克风可用并要求不再实证，参考基线按“用户确认，未测量”登记。

校准中的失败尝试也保留：Electron导出落点、Python中文stdin编码、测试器漏传expected参数、中文数值“三百/300”的等价判据、音频采集后的截图超时，以及看图复核发现的归还后成员筛选未刷新、文档错误提示直接展示traceback。后两项分别增加刷新断言和中文错误可读性断言。修复仅涉及参考应用和校准工具；没有修改Bloma制作/验收机制，没有修改参赛产物或任务分值。成功证据由新目录完整运行产生，不把失败记录改成成功。

## 人工正反例判据

| 检查类别 | 正例 | 反例或未验证 |
| --- | --- | --- |
| 语音转写 | 固定录音的公开事实与实体录音均正确出现 | 仅显示固定文本；导入成功但实体录音未执行时该项未验证 |
| 上下文 | 第三轮准确说出语音助手、周五、300元、蓝色，服务请求含历史 | 固定回复碰巧含一个关键词；遗漏当前发言 |
| 完整朗读 | 对应文本的整段声音可听到自然结束 | 播放标签变完成但中途停止，或音频与当前气泡无关 |
| 空录音/取消 | 无新消息和服务请求，之后正常说话成功 | 将空输入当作有效句子，取消后仍发请求 |
| 设置和记录重启 | 全部产品进程结束后重新启动，读回并继续成功 | 只刷新页面；测试重开前重新注入设置 |
| 跨对象业务 | 所有成员、器材、数量逐项对应 | 总数正确但成员归属错误 |
| 异常原子性 | 失败前后账目一致，合法操作可继续 | 已扣库存却未保存明细 |
| 导入导出 | 新空实例能恢复完整账目 | 导出文件存在但缺借还明细 |
| 来源检索 | 正确相对文件身份和页/行，可打开对应片段 | 重名文件覆盖；返回关键词但位置错误 |
| 文档语义 | 所选事实准确、来源可核对 | 混入未选文档旧预算；引用无法对应 |
| 队列取消/恢复 | 取消指定排队项，其他任务继续，失败项可重试 | 停止整个队列；失败状态直接改成功 |
| 可使用性 | 交付入口及操作路径可由普通用户完成 | 需要操作者手改源码或补写开发命令 |

两名评判者先对本表独立分类，记录分歧，再开始实际成品评分。分歧未解决的检查标 unverified。任何调整判据都应发布新包版本并对所有系统同样应用。

## 发布状态

本版冻结输入、评分、公共配置与外部验收方法，三个参考应用已经完成单机端到端校准，可以开始Bloma与通用Agent的pilot采集。正式比较仍按原检查项评分；不会因参考应用成功而预先给参赛系统分数。

两名独立评判者的语义和听音标注仍需登记，不能由脚本或单个开发者代签。因此ranking_enabled=false继续保留，pilot分数与完成率可以如实记录，正式研究排名待独立评判完成后按同一冻结标准发布。这项人工标注可以与制作试验并行，不要求Agent额外生成审查材料。
