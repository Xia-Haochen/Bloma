# 语音对话外部验收

标准输入为01-name.wav、02-budget.wav、03-recall.wav及silence.wav。前三段由独立的基准准备工具预生成，作为固定音频输入；transcripts.json给出人工核对文本。产品TTS不能替代这些输入。先对照文本试听输入，记录评估者。

| 检查 | 外部操作与预期 |
| --- | --- |
| B1 | 依次导入三段固定音频，经正常产品语音入口转写，检查小林、语音助手、周五、三百元、蓝色等事实。另用实体麦克风读第一句，身份信息与识别结果一致。 |
| B2 | 受控服务检查每次请求含当前发言及前轮双方内容。再用统一真实模型运行新会话，同样三轮，第三轮答案应正确回忆项目语音助手、周五交付、预算300元和蓝色主题。两名评判者逐事实标记。 |
| B3 | 每轮录制应用音频输出及显示文字，听到全部内容，播放器自然结束；连续发送下一轮时前轮音频保持完整。记录播放开始/结束与文字。不得只看“已朗读”标签。 |
| R1 | silence.wav输入与一次用户取消录音均不能产生伪造文本或服务请求，状态明确。之后第一段正常录音成功。 |
| R2 | 在受控服务的control.json中设置fail_next=1，触发一次503。再设置auth_key为changed-key使旧配置失效，界面准确提示鉴权失败。使用正常设置更新密钥后成功继续，历史完整。 |
| P1 | 保存角色/服务设置，关闭全部产品进程后重开，不重新配置即可请求。先关闭外部服务会导致此项无效，应保持服务实例运行。 |
| P2 | 重开前后逐条比对三轮文本，继续询问四项事实，历史与上下文完整。 |
| U1 | 正常启动入口与录音、停止、设置、历史操作均通过界面完成。 |
| U2 | 录音、转写、等待、播放、成功和错误各状态能被普通用户识别，双方消息可区分。 |

实体录音标准句为“我叫小林，我的项目叫语音助手，计划周五交付”。两组使用同一设备、相同设备设置、相同音量范围和同一操作者。取消操作和空录音分别执行，不把录音许可失败当作取消成功。

“小林”等专名若有同音字，按公开事实能否明确对应判断，两名评判者记录原文及理由。模型事实回忆必须四项全部正确。音频录制设备和听音方法在study.json登记，两组一致。
