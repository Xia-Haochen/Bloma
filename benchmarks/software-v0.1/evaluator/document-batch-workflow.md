# 文档批处理外部验收

使用inputs/documents中的六份有效文档、一个损坏PDF和一个不支持的UTF-16文件。支持范围为UTF-8 TXT/Markdown及带文本层PDF。文件身份以相对路径区分，a/项目纪要.txt和b/项目纪要.txt名称相同。

| 检查 | 外部操作与预期 |
| --- | --- |
| B1 | 导入六份有效文档，逐份对照facts.json核对中文文本，重名文件内容分别保留。 |
| B2 | 搜索“青禾”，返回facts.json登记的文件及页/行位置；打开每个结果并核对片段。清空过滤后六份文件都可见。 |
| B3 | 选中a/项目纪要.txt、预算.md、交付.pdf，受控服务收到三份内容；使用统一真实模型输出摘要与汇总，核对三份中的关键事实和来源，未选文档的3000元旧预算不得混入。 |
| R1 | 导入损坏PDF及UTF-16文件，标明具体文件问题，有效文档继续可用。受控服务delay_ms=5000，排入至少三项，取消尚未开始的一项，该项不产生伪完成结果。 |
| R2 | fail_next=1，仅当前任务失败，已完成任务结果保留。清除故障并重试失败项成功，已完成项无重复覆盖。运行前后原始文件SHA-256一致。 |
| P1 | 所有任务结束或取消后关闭全部产品进程，重开读回文档索引、配置、每项状态及已有结果。 |
| P2 | 导出所选结果为Markdown与CSV，逐文件核对中文、来源与状态。失败/取消项不能被写成成功摘要。 |
| U1 | 导入、搜索、排队、取消、重试、导出均走正常界面。运行中尝试选择其他文档，界面仍响应。 |
| U2 | 每项任务的输入身份、状态及错误可见，结果能定位来源。 |

把实际导出及UI观察转换成document-facts.json供自动核对，保留原始导出和对应录屏。自动核对仅覆盖事实与文件映射；模型语义、来源可操作性、取消和UI响应由外部步骤验证。
